This tutorial shows you how to serve a large language model across multiple GPU nodes using a [Ray Cluster](/instant-clusters/ray-clusters). The supported Ray cluster image starts Ray on every node and runs vLLM for you, so you configure the deployment with environment variables and never build an image or run a startup script.

vLLM splits the model across GPUs within each node with tensor parallelism, and across nodes with pipeline parallelism. This lets you serve models that don't fit in the memory of a single node.

## What you'll learn

In this tutorial, you'll learn how to:

- Create a Ray Cluster with the Ray Cluster template.
- Configure the model to serve with environment variables.
- Check that every node has joined the Ray cluster.
- Send requests to the OpenAI-compatible vLLM API.
- Monitor the cluster in the Ray dashboard.

## Requirements

- A Runpod account with enough credits for a multi-node cluster.
- A [Hugging Face access token](https://huggingface.co/settings/tokens) if the model you serve is gated or private.

## Step 1: Create a Ray Cluster

{/* TODO(DOCS-609): verify every console label in this step against the live create flow (cluster type selector, template name, env var editing) once the Ray Clusters flag is on. */}

1. Open the [Instant Clusters page](https://console.runpod.io/instant-clusters) and click **Create Cluster**.
2. Select **Ray** as the cluster type.
3. Name your cluster, set **Pod Count** to **2**, and select **8x H100 SXM** as the GPU configuration for each Pod.
4. Optionally, select a [network volume](/storage/network-volumes) to share model weights across nodes.
5. Confirm that the **Ray Cluster** template is selected. The console selects it automatically for Ray Clusters. Ray Clusters only accept the supported Ray cluster image or images built from it.
6. Click **Edit Template** and add the following environment variables:

   | Variable | Value |
   | --- | --- |
   | `MODEL_REPO` | `Qwen/Qwen3-235B-A22B` |
   | `HF_TOKEN` | Your Hugging Face token, if the model is gated. |

   You can also set `VLLM_API_KEY`, `MAX_MODEL_LENGTH`, and `VLLM_EXTRA_ARGS`. See [serve a model with the inference variant](/instant-clusters/ray-clusters#serve-a-model-with-the-inference-variant) for every option.

7. Click **Deploy Cluster**.

Runpod deploys one Pod per node. The Pod with rank `0` is the Ray head node, and the other Pods are workers.

## Step 2: Check that the cluster is ready

Each Pod starts Ray as soon as its container starts. Workers wait for the head node, then join. After every node has joined, the head node starts vLLM.

The status shown on the cluster card reflects the requested cluster, not whether Ray is ready. Use `ray status` on the head node to check that every node has joined.

1. On the Instant Clusters page, expand your cluster and select the head Pod (rank `0`).
2. Click **Connect**, then open a **Web Terminal**.
3. Check the state of the Ray cluster:

   ```bash
   ray status
   ```

   When both nodes have joined, the output lists 2 healthy nodes and 16 GPUs:

   ```text
   ======== Autoscaler status: 2026-11-17 10:00:00 ========
   Node status
   ---------------------------------------------------------------
   Active:
    1 node_...
    1 node_...
   ...
   Resources
   ---------------------------------------------------------------
   Usage:
    0.0/16.0 GPU
   ```

4. Attach to the vLLM session to follow model loading:

   ```bash
   screen -r
   ```

   Press `Ctrl+A`, then `D`, to detach without stopping vLLM.

Downloading and loading a large model across nodes can take several minutes. vLLM is ready when its log shows that the API server has started.

## Step 3: Send a request

The head node exposes the vLLM API through the Runpod proxy on port `8001`. While the model is loading, this port returns a `503` response.

Every request needs the API key in `VLLM_API_KEY`. If you didn't set one, the default is `sk-` followed by the head Pod's ID, for example `sk-abc123xyz`.

1. List the models served by the cluster:

   ```bash
   curl https://HEAD_POD_ID-8001.proxy.runpod.net/v1/models \
       -H "Authorization: Bearer VLLM_API_KEY"
   ```

2. Send a chat completion request:

   ```bash
   curl https://HEAD_POD_ID-8001.proxy.runpod.net/v1/chat/completions \
       -H "Authorization: Bearer VLLM_API_KEY" \
       -H "Content-Type: application/json" \
       -d '{
           "model": "Qwen/Qwen3-235B-A22B",
           "messages": [{"role": "user", "content": "Explain pipeline parallelism in one sentence."}]
       }'
   ```

Replace `HEAD_POD_ID` with the ID of the head Pod and `VLLM_API_KEY` with your API key.

Because the API is OpenAI-compatible, you can also use the OpenAI Python client:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://HEAD_POD_ID-8001.proxy.runpod.net/v1",
    api_key="VLLM_API_KEY",
)

response = client.chat.completions.create(
    model="Qwen/Qwen3-235B-A22B",
    messages=[{"role": "user", "content": "Explain pipeline parallelism in one sentence."}],
)
print(response.choices[0].message.content)
```

This script points the OpenAI client at your cluster's vLLM server and prints the model's reply.

## Step 4: Monitor the cluster

1. Select the head Pod and click **Connect**.
2. Click **Ray Dashboard**. The console signs you in with the head node's token.
3. Open the **Cluster** tab to see live CPU, GPU, memory, and disk usage for each node.
4. Open the **Metrics** tab to see historical charts for every node and vLLM serving metrics.

See [open the Ray dashboard](/instant-clusters/ray-clusters#open-the-ray-dashboard) for token details and troubleshooting.

## Step 5: Clean up

When you're done, return to the [Instant Clusters page](https://console.runpod.io/instant-clusters) and delete your cluster. A running cluster continues to incur charges.
