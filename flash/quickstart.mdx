<Warning>
  Flash is now part of the [Runpod SDK](/sdk/overview). This page documents the standalone `runpod-flash` package, which stops getting fixes and updates after its [deprecation date](/flash/overview). For new projects, use the [Runpod SDK quickstart](/sdk/quickstart). To see how Flash commands and imports map to the SDK, see [Migrating from Flash](/sdk/migrate-from-flash).
</Warning>

This quickstart gets you running GPU workloads on Runpod in minutes. You'll execute a function on a remote GPU and see the results immediately.

## Requirements

- [Runpod account](/accounts-billing/manage-accounts) with a verified email address.
- [An API key](/get-started/credentials#api-keys) with **All** access permissions to your Runpod account.
- [Python 3.10 to 3.14](https://www.python.org/downloads/) installed. Workers run Python 3.12 by default, whatever your local version.
- [uv](https://docs.astral.sh/uv/) installed.

## Step 1: Install Flash

<Note>
Flash runs natively on macOS and Linux. Windows users can run Flash through [WSL2](/flash/windows-wsl2).
</Note>

Create a virtual environment and install Flash using [uv](https://docs.astral.sh/uv/):

```bash
uv venv
source .venv/bin/activate
uv pip install runpod-flash
```

<Tip>

When you create a project with `flash init`, Flash generates `AGENTS.md` (and `CLAUDE.md` as a symlink) with CLI-first rules for AI coding assistants. These files tell AI tools like Claude Code, Cursor, and Codex to use Flash commands instead of raw Runpod API calls. See [`flash init`](/flash/cli/init) for details.

</Tip>

### Optional: Install coding agent integration

If you're using an AI coding agent like Claude Code, Cline, or Cursor, you can install the Flash skill package to give your agent detailed context about the Flash SDK:

```bash
npx skills add runpod/runpod-plugins-official
```

This enables your coding agent to provide more accurate Flash code suggestions and troubleshooting help.

## Step 2: Authenticate with Runpod

Log in to your Runpod account:

```bash
flash login

# If using uv:
uv run flash login
```

This opens your browser to authorize Flash. After you approve, your credentials are saved, allowing you to run Flash commands and scripts.

<Tip>
Alternatively, you can set the `RUNPOD_API_KEY` environment variable or add it to a `.env` file. See [`flash login`](/flash/cli/login) for details.
</Tip>

## Step 3: Copy this code

Create a file called `gpu_demo.py` and paste this code into it:

```python
import asyncio
from runpod_flash import Endpoint, GpuGroup

@Endpoint(
    name="flash-quickstart",
    gpu=GpuGroup.ANY, # Use any available GPU
    workers=3,
    idle_timeout=300, # Keep worker running for 5 minutes
    dependencies=["numpy", "torch"]
)
def gpu_matrix_multiply(size):
    # IMPORTANT: Import packages INSIDE the function
    import numpy as np
    import torch

    # Get GPU name
    device_name = torch.cuda.get_device_name(0)

    # Create random matrices
    A = np.random.rand(size, size)
    B = np.random.rand(size, size)

    # Multiply matrices
    C = np.dot(A, B)

    return {
        "matrix_size": size,
        "result_mean": float(np.mean(C)),
        "gpu": device_name
    }

# Call the function
async def main():
    print("Running matrix multiplication on Runpod GPU...")
    result = await gpu_matrix_multiply(1000)

    print(f"\n✓ Matrix size: {result['matrix_size']}x{result['matrix_size']}")
    print(f"✓ Result mean: {result['result_mean']:.4f}")
    print(f"✓ GPU used: {result['gpu']}")

if __name__ == "__main__":
    asyncio.run(main())
```

<Warning>
Make sure you activate your virtual environment in the same directory where you created the `gpu_demo.py` file. If you open a new terminal, run `source .venv/bin/activate` before executing the script.
</Warning>

## Step 4: Deploy the endpoint

From the directory that contains `gpu_demo.py`, deploy the endpoint:

```bash
flash deploy

# If using uv:
uv run flash deploy
```

Flash builds your project on your machine, uploads it, and creates the `flash-quickstart` endpoint. The app is named after the current directory, and the endpoint is deployed to the `production` environment:

```text
✓ built quickstart  2 files, 1 deps, 15.8 MB
No app 'quickstart' found. Creating app and 'production' environment...

✓ uploaded  15.8 MB  2.2s
✓ deployed to production  2.0s

  flash-quickstart  https://api.runpod.ai/v2/abc123xyz/runsync
```

The URL contains your endpoint ID (`abc123xyz` here). You'll use it in [Step 9](#step-9-call-the-endpoint-from-any-language) to call the endpoint over HTTP.

<Note>
Every `flash` command and script prints a deprecation notice (a `FutureWarning` in scripts) because `runpod-flash` is moving into the [Runpod SDK](/sdk/overview). The notice doesn't affect your deployment.
</Note>

<Note>
`flash deploy` installs your endpoint's dependencies into a local build directory before uploading. Flash leaves `torch`, `torchvision`, `torchaudio`, and `triton` out of the upload because the worker image already provides them, but a dependency that requires `torch` (such as `accelerate`) still downloads it during the local build. On Linux, that can be several GB. If the build runs out of disk space, remove that dependency, exclude it with `--exclude`, or skip transitive dependencies with `--no-deps`. See [`flash deploy`](/flash/cli/deploy) for details.
</Note>

## Step 5: Run it

Execute the script from the same directory:

```bash
python gpu_demo.py
```

Flash sends the call to your deployed endpoint and prints the result:

```text
Running matrix multiplication on Runpod GPU...

✓ Matrix size: 1000x1000
✓ Result mean: 249.8286
✓ GPU used: NVIDIA RTX A5000
```

The first run takes about a minute while a worker starts. Later runs return in a few seconds while the worker is still warm.

<Warning>
The first request on a new worker can take longer than the 90 seconds `runpod-flash` 1.21.0 waits for a result, especially if the worker has to wait for a free GPU. If the script fails with `timed out after 90s. the endpoint may not be deployed or the worker is still starting` or `KeyError: 'matrix_size'`, the endpoint is deployed and the worker is still starting. Run the script again. See [First run fails after 90 seconds](#first-run-fails-after-90-seconds).
</Warning>

<Warning>
If you see `endpoint 'flash-quickstart' not found in app '...' environment 'production'`, the endpoint isn't deployed for this directory. Run `flash deploy` from the directory that contains `gpu_demo.py`, then run the script again from that same directory.
</Warning>


<Tip>
If you're having authorization issues, you can set your API key directly in your terminal:

```bash
export RUNPOD_API_KEY="your_key"
```

Replace `your_key` with your actual API key from the [Credentials page](https://console.runpod.io/user/credentials).
</Tip>

## Step 6: Update and run again

With your endpoint running, change an input and run the script again:

1. Open `gpu_demo.py` and change the matrix size from `1000` to `2000`:

   ```python
   result = await gpu_matrix_multiply(2000)
   ```

2. Run the script again:

   ```bash
   python gpu_demo.py
   ```

This time, the result should appear in a few seconds because the worker is already warm. The argument is sent with the request, so you don't need to redeploy.

If you change the code inside `gpu_matrix_multiply` or its `@Endpoint` configuration, run `flash deploy` again so the endpoint picks up the new version.

## Step 7: Understand what you just did

Let's break down the code you just ran:

### Imports and setup

```python
import asyncio
from runpod_flash import Endpoint, GpuGroup
```

- **`asyncio`**: Enables asynchronous execution (endpoint functions run async).
- **`Endpoint`**: The class that marks functions for remote execution.
- **`GpuGroup`**: Enum for selecting GPU types or groups of GPUs.

Flash automatically loads your credentials from `flash login` or the `RUNPOD_API_KEY` environment variable.

### The `@Endpoint` decorator

```python
@Endpoint(
    name="flash-quickstart",
    gpu=GpuGroup.ANY,
    workers=3,
    idle_timeout=300,
    dependencies=["numpy", "torch"]
)
def gpu_matrix_multiply(size):
    import numpy as np
    import torch

    # Get GPU name
    device_name = torch.cuda.get_device_name(0)

    # Create random matrices
    A = np.random.rand(size, size)
    B = np.random.rand(size, size)

    # Multiply matrices
    C = np.dot(A, B)

    return {
        "matrix_size": size,
        "result_mean": float(np.mean(C)),
        "gpu": device_name
    }
```

The `@Endpoint` decorator configures everything in one place:

- **`name`**: Identifies your endpoint in the [Runpod console](https://console.runpod.io/serverless).
- **`gpu`**: Which GPU to use (`GpuGroup.ANY` accepts any available GPU for faster provisioning).
- **`workers`**: Maximum parallel workers (allows 3 concurrent executions).
- **`idle_timeout`**: Seconds a worker stays active after completing a request before scaling down. Setting this to 300 (5 minutes) gives you more time to iterate on your code while the worker remains warm.
- **`dependencies`**: Python packages to install on the worker.
- **Function body**: The matrix multiplication code runs on the remote GPU, not your local machine.
- **Return value**: The result is returned to your local machine as a Python dictionary.

See [GPU types](/flash/configuration/gpu-types) for available GPUs or [endpoint functions](/flash/create-endpoints) for all configuration options.

<Warning>
You must import packages **inside the function body**, not at the top of your file. These imports need to happen on the remote worker.
</Warning>

### Calling the function

```python
async def main():
    print("Running matrix multiplication on Runpod GPU...")
    result = await gpu_matrix_multiply(1000)

    print(f"\n✓ Matrix size: {result['matrix_size']}x{result['matrix_size']}")
    print(f"✓ Result mean: {result['result_mean']:.4f}")
    print(f"✓ GPU used: {result['gpu']}")

if __name__ == "__main__":
    asyncio.run(main())
```

Here's what happens when you call an `@Endpoint` decorated function:

1. Flash looks up the endpoint by its `name` in your app (the current directory name) and environment (`production` by default). `flash deploy` must have created it first.
2. Flash sends the function's arguments to the endpoint.
3. A GPU worker runs the deployed function with those arguments.
4. The result is returned to your local machine as a Python dictionary, where it's printed in your terminal.

Everything outside the `@Endpoint` function (all the `print` statements, etc.) runs **locally on your machine**. Only the decorated function runs remotely.

## Step 8: Run multiple operations in parallel

Flash makes it easy to run multiple GPU operations concurrently. Replace your `main()` function with the code below, and keep the `if __name__ == "__main__":` block at the end of the file. Without it, the script exits without printing anything.

```python
async def main():
    print("Running 3 matrix operations in parallel...")

    # Run all three operations at once
    results = await asyncio.gather(
        gpu_matrix_multiply(500),
        gpu_matrix_multiply(1000),
        gpu_matrix_multiply(2000)
    )

    # Print results
    for i, result in enumerate(results, 1):
        print(f"\n{i}. Size: {result['matrix_size']}x{result['matrix_size']}")
        print(f"   Mean: {result['result_mean']:.4f}")
        print(f"   GPU: {result['gpu']}")

if __name__ == "__main__":
    asyncio.run(main())
```

You only changed code outside the `@Endpoint` function, so you don't need to redeploy. Run the script again:

```bash
python gpu_demo.py
```

All three operations execute simultaneously:

```text
Running 3 matrix operations in parallel...

1. Size: 500x500
   Mean: 125.3097
   GPU: NVIDIA RTX A5000

2. Size: 1000x1000
   Mean: 249.9442
   GPU: NVIDIA RTX A5000

3. Size: 2000x2000
   Mean: 500.1321
   GPU: NVIDIA RTX A5000
```

## Step 9: Call the endpoint from any language

Your endpoint is a standard [Serverless endpoint](/serverless/endpoints/send-requests), so any language that can send HTTP requests can call it. The JSON `input` object holds the function's arguments by name.

Submit a job with `/run`, using the endpoint ID from Step 4:

```bash
curl -X POST https://api.runpod.ai/v2/ENDPOINT_ID/run \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $RUNPOD_API_KEY" \
  -d '{"input": {"size": 500}}'
```

```json
{"id": "50e2248c-55c3-4f61-b633-35e447a4d82d-u2", "status": "IN_QUEUE"}
```

Then poll `/status` with the job ID until `status` is `COMPLETED`:

```bash
curl https://api.runpod.ai/v2/ENDPOINT_ID/status/JOB_ID \
  -H "Authorization: Bearer $RUNPOD_API_KEY"
```

```json
{
  "id": "50e2248c-55c3-4f61-b633-35e447a4d82d-u2",
  "status": "COMPLETED",
  "output": {"gpu": "NVIDIA RTX A5000", "matrix_size": 500, "result_mean": 124.87},
  "delayTime": 15,
  "executionTime": 189
}
```

Use `/run` and `/status` for long jobs and cold starts. `/runsync` returns the result in one request but waits at most 90 seconds by default, then returns `IN_QUEUE` or `IN_PROGRESS` and you poll `/status` anyway.

<Warning>
Always send at least one key in `input`. Runpod drops a job whose `input` is empty (`{"input": {}}`), and after about 40 seconds it fails with `job timed out after 1 retries`. The curl example that `flash deploy` prints in `runpod-flash` 1.21.0 and earlier uses an empty `input`, so replace it with your function's arguments.
</Warning>

```bash

flash undeploy flash-quickstart

# Or remove all endpoints

uv run flash undeploy list
uv run flash undeploy flash-quickstart
uv run flash undeploy --all
```

## Troubleshooting

### Endpoint not found

```text
RuntimeError: endpoint 'flash-quickstart' not found in app 'Quickstart' environment 'production'. deploy it first with 'flash deploy'.
```

**Solution**: Calling an `@Endpoint` function sends the request to an endpoint you've already deployed. Run `flash deploy` from the directory that contains your script, then run the script from that same directory. Flash uses the directory name as the app name, so running from a different directory looks up a different app.

### First run fails after 90 seconds

**Issue**: The first run fails with one of these errors:

```text
RuntimeError: request to endpoint 'flash-quickstart' timed out after 90s. the endpoint may not be deployed or the worker is still starting. deploy with 'flash deploy' or increase timeout with FLASH_SENTINEL_TIMEOUT env var.
```

```text
KeyError: 'matrix_size'
```

**Cause**: `runpod-flash` 1.21.0 waits up to 90 seconds for a result. The first request on a new worker can take longer: the worker may wait for a free GPU, then it starts and loads the model. The endpoint is deployed, and the request keeps running after the error.

**Solution**: Run the script again. The worker keeps starting after the error, so the next run is faster. Raising `FLASH_SENTINEL_TIMEOUT` above 90 doesn't help in 1.21.0: the request returns at 90 seconds with the job still running, and the script fails with the `KeyError` instead.

To see whether a worker is up, check the endpoint's health with its ID from `flash deploy`:

```bash
curl https://api.runpod.ai/v2/ENDPOINT_ID/health \
  -H "Authorization: Bearer $RUNPOD_API_KEY"
```

`"throttled": 1` means the worker is waiting for a GPU. `"idle"` or `"running"` means it's ready.

### Job timed out after 1 retries

```text
RuntimeError: remote execution failed: job timed out after 1 retries
```

**Solution**: The worker stopped responding while it held the job. Two common causes:

- **Empty input over HTTP**: a request with `{"input": {}}` never reaches your function. Send at least one argument, as shown in [Step 9](#step-9-call-the-endpoint-from-any-language).
- **Redeploying during a request**: `flash deploy` replaces running workers, so a request that's in progress fails. Wait for running requests to finish before you redeploy, or run the request again.

### Authentication error

`flash` commands print:

```text
No RunPod API key found. Set one with:
```

Scripts that call an endpoint fail with:

```text
httpx.HTTPStatusError: Client error '401 Unauthorized' for url 'https://api.runpod.ai/v2/flash/runsync'
```

**Solution**: Run `flash login` to authenticate with your Runpod account:

```bash
flash login

# If using uv:
uv run flash login
```

Alternatively, set the `RUNPOD_API_KEY` environment variable:

```bash
export RUNPOD_API_KEY="your_key"
```

### Template name conflict

```text
Error: endpoint template names must be unique
```

**Solution**: Each endpoint needs a unique `name`. If you've deployed an endpoint before with the same name, either:
- Use a different name for your new endpoint
- Undeploy the existing endpoint with `flash undeploy <name> --force`

### Job stuck in queue

Requests wait for minutes, and the endpoint's [health check](#first-run-fails-after-90-seconds) shows `"throttled": 1` with no idle or running workers.

**Solution**: No GPU of the types you selected is free. `GpuGroup.ANY` (used in this quickstart) accepts any available GPU. If you narrowed `gpu` to specific types, list several so Flash can fall back:

```python
from runpod_flash import Endpoint, GpuType

@Endpoint(
    name="flash-quickstart",
    gpu=[
        GpuType.NVIDIA_GEFORCE_RTX_4090,
        GpuType.NVIDIA_RTX_A5000,
        GpuType.NVIDIA_RTX_A6000
    ],
    dependencies=["numpy", "torch"]
)
def gpu_matrix_multiply(size):
    ...
```

You can also check [GPU availability](https://console.runpod.io/serverless) in the console.

### Import errors

```text
ModuleNotFoundError: No module named 'numpy'
```

**Solution**: Move imports inside the `@Endpoint` function:

```python
@Endpoint(name="compute", gpu=GpuGroup.ANY, dependencies=["numpy"])
def my_function():
    import numpy as np  # Import here, not at top of file
    # ...
```

See the [execution model](/flash/execution-model#common-execution-issues) for more troubleshooting.
