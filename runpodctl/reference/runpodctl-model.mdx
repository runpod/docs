Manage models in the Runpod model repository. You can add a model from a local directory or mirror one from Hugging Face, list your models, and remove ones you no longer need.

<RequestExample>
```bash Command
runpodctl model <subcommand> [flags]
```
</RequestExample>

## Subcommands

### List models

List the models in your model repository:

```bash
runpodctl model list
```

You can use `ls` as a shorthand for `list`.

#### List flags

<ResponseField name="--name" type="string">
Filter by model name.
</ResponseField>

<ResponseField name="--provider" type="string">
Filter by provider.
</ResponseField>

### Add a model

Add a model by mirroring a Hugging Face repository. `--name` is the name the model gets in your repository, and `--huggingface-model` is the source:

```bash
runpodctl model add --name tiny-llm --huggingface-model arnir0/Tiny-LLM
```

Add a model by uploading a local directory of model files:

```bash
runpodctl model add --name my-model --model-path ./my-model-dir
```

To wait until the uploaded model is ready to deploy, add `--wait-for-hash`. To also delete the local files once the upload is confirmed, add `--delete-my-model-files-after-upload`:

```bash
runpodctl model add --name my-model --model-path ./my-model-dir \
  --wait-for-hash --delete-my-model-files-after-upload
```

`--huggingface-model` can't be combined with the local upload flags, such as `--model-path`.

<Warning>

`--delete-my-model-files-after-upload` deletes the files in `--model-path` from your machine. It requires `--wait-for-hash`, so files are deleted only after the model version is confirmed deployable.

</Warning>

If your account has a model repository storage quota, a local upload checks the total size of the files against your remaining quota before it creates anything. An upload that would exceed the quota fails right away, and the error shows how much space is available. Free up space or contact support to request a higher quota. Mirroring with `--huggingface-model` doesn't run this check.

### Remove a model

Remove a model from your repository. Both `--name` and `--owner` are required:

```bash
runpodctl model remove --owner <owner> --name my-model
```

You can use `rm` or `delete` as a shorthand for `remove`.

To remove a single version instead of the whole model, pass `--version` or `--hash`:

```bash
runpodctl model remove --owner <owner> --name my-model --version <version-uuid>
```

A model or version that a Serverless endpoint still references can't be removed, and there is no flag to force it. Removing the whole model fails if an endpoint references any of its versions. Removing one version fails only if an endpoint references that version. The command lists the endpoints that block the removal and deletes nothing. If `runpodctl` can't complete this check, for example because the API is unreachable, it also refuses the removal.

Detach the model from each endpoint first, or point the endpoint at a different model with `--model-reference`, then remove it:

```bash
runpodctl serverless update <endpoint-id> --clear-models
runpodctl model remove --owner <owner> --name my-model
```

#### Remove flags

<ResponseField name="--name" type="string" required>
Name of the model to remove.
</ResponseField>

<ResponseField name="--owner" type="string" required>
Owner of the model.
</ResponseField>

<ResponseField name="--version" type="string">
UUID of a specific model version to remove. Can't be combined with `--hash`.
</ResponseField>

<ResponseField name="--hash" type="string">
Hash of a specific model version to remove. Can't be combined with `--version`.
</ResponseField>
