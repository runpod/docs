Configure the Runpod CLI with your API credentials and API URL to enable programmatic access to your Runpod resources.

<RequestExample>
```bash Command
runpodctl config [flags]
```
</RequestExample>

## Example

Configure the CLI with your API key:

```bash
runpodctl config --apiKey "your-api-key-here"
```

<Note>

For first-time setup, we recommend using [`runpodctl doctor`](/runpodctl/reference/runpodctl-doctor) instead, which guides you through API key configuration and SSH key setup interactively.

</Note>

## Where your API key is stored

`runpodctl` saves your API key in plaintext in `~/.runpod/config.toml`. On Linux and macOS, the CLI creates this file with `0600` permissions inside a `0700` directory, so only your user account can read it. Each time `runpodctl` runs, it also removes group and world access from the existing directory, the config file, and the legacy `~/.runpod.yaml` file if one exists. If it can't check or change these permissions, it prints a warning and the command still runs.

On Windows, the config file inherits the access control lists (ACLs) of its parent directory. `runpodctl` doesn't change these ACLs, so whether other users can read the file depends on how that directory is configured.

<Warning>

Earlier versions of `runpodctl` created the config file with permissions that let other users on the same machine read it. If you've used `runpodctl` on a shared machine, [delete your existing API key](/get-started/credentials#delete-an-api-key), create a new one, and save it with `runpodctl config --apiKey`. Tightening the file's permissions doesn't undo any earlier exposure.

</Warning>

## Flags

<ResponseField name="--apiKey" type="string">
Your Runpod API key, which authenticates the CLI to access your account. You can generate an API key from the [Runpod console](https://console.runpod.io/user/settings).
</ResponseField>

<ResponseField name="--apiUrl" type="string" default="https://api.runpod.io/graphql">
The Runpod API endpoint URL. The default value should work for most users.
</ResponseField>
