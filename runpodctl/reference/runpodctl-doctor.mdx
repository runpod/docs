Diagnose and fix CLI issues, including first-time setup for API keys and SSH configuration.

<RequestExample>
```bash Command
runpodctl doctor [flags]
```
</RequestExample>

## Description

The `doctor` command is the recommended way to set up `runpodctl` for the first time. It runs three checks in order, and each one runs only if the previous one passed:

1. **API key:** Confirms that an API key is configured. If none is, `doctor` asks for one, checks it with the Runpod API, and saves it to `~/.runpod/config.toml`.
2. **API connectivity:** Confirms that `runpodctl` can reach the Runpod API with the configured key.
3. **SSH key:** Sets up an SSH key for Pod access.

`doctor` saves a new API key only after the Runpod API accepts it. A rejected key is never written to your configuration, so a typo can't replace a working key.

`doctor` prints its report to stdout as JSON (or YAML with `--output yaml`) and exits with a non-zero status whenever any check fails. Scripts and CI jobs can rely on the exit code to detect a broken setup.

## Examples

Run `doctor` with no arguments to set up or troubleshoot the CLI interactively. If no API key is configured, it prompts you to paste one:

```bash
runpodctl doctor
```

In CI, containers, or agent-driven environments, pipe the key to `doctor` on stdin. This keeps the key out of your shell history and the process list. In this example, `MY_RUNPOD_KEY` is a variable that holds your key, such as a CI secret:

```bash
printf %s "$MY_RUNPOD_KEY" | runpodctl doctor
```

`doctor` reads stdin only when no API key is configured. If a key is already saved or the `RUNPOD_API_KEY` environment variable is set, the piped key is ignored.

To set a key even when one is already saved, pass it with `--api-key`. This replaces the saved key:

```bash
runpodctl doctor --api-key YOUR_API_KEY
```

## Flags

<ResponseField name="--api-key" type="string">
An API key to check with the Runpod API and save to your configuration, replacing any saved key. The key is visible in your shell history and the process list, so prefer piping it on stdin when no key is saved yet. If `RUNPOD_API_KEY` is set to a different key, `doctor` still saves this key but warns that the environment variable takes precedence. Unset `RUNPOD_API_KEY` to use the saved key. An empty value, such as an unset shell variable, is an error.
</ResponseField>

<ResponseField name="--output" type="string" default="json">
The report format: `json` or `yaml`.
</ResponseField>
