Receive files or folders sent from another machine using a secure peer-to-peer connection established with a connection code.

<RequestExample>
```bash Command
runpodctl receive <code>
```
</RequestExample>

## Example

Receive files using a connection code:

```bash
runpodctl receive rainbow-unicorn-42
```

## Arguments

<ResponseField name="<code>" type="string" required>
The connection code phrase that matches the code used by the sender with the [`send`](/runpodctl/reference/runpodctl-send) command.
</ResponseField>

## What receive writes

`runpodctl receive` writes only inside the directory you run it from. The sender chooses the file names and paths, so `receive` checks the full list of incoming files before it writes anything. If any entry fails the check, `receive` refuses the whole transfer rather than writing part of it. Both the sender and the receiver see the reason.

`receive` refuses a transfer that would do any of the following:

- Write to an absolute path, or to a path that contains `..` or a backslash.
- Create a symlink whose target resolves outside the destination directory.
- Write through a symlink that already exists in the destination, such as a symlinked subdirectory that points outside it.
- Declare the same path twice with different contents, or use one path as both a file and a directory.
- Replace an existing file with a directory, or an existing directory with a file.

Symlinks that point to locations inside a transferred folder transfer normally. If `receive` refuses a folder transfer after its archive arrives, it keeps the archive in the destination. The error message shows where the archive is.

### Receive into a symlinked directory

`receive` refuses a transfer that writes into a symlinked subdirectory when the symlink points outside the current directory. To receive the files, run `receive` from inside the directory the symlink points to, or replace the symlink with a real directory.
