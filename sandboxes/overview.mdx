Sandboxes are short-lived, isolated CPU environments that you create on demand, run commands in, and tear down when you're done. They're built for running untrusted code: code generated by an AI agent, code submitted by your users, or one-off scripts you don't want touching your own infrastructure.

You manage sandboxes through the [REST API v2](/api-reference-v2/overview). Each sandbox runs a container image you choose, a Runpod template or the default image, and is billed per second until it terminates.

## When to use a sandbox

Use a sandbox when you need a clean, disposable environment for a short task:

- An AI agent needs to run the code it writes.
- Your application runs code or commands supplied by end users.
- You want to test a script or package in isolation before running it elsewhere.

For long-running workloads, GPU compute, or persistent development environments, use [Pods](/pods/overview) instead. For request-driven inference that scales with traffic, use [Serverless](/serverless/overview).

## Isolation

Every sandbox runs under [gVisor](https://gvisor.dev/), a user-space kernel that intercepts the container's system calls. Code inside a sandbox can't reach the host machine or other users' sandboxes, so you can run code you don't trust.

## How sandboxes work

1. **Create** a sandbox from the default image, a Runpod template, or your own image. It starts in seconds and is billed per second.
2. **Run commands** in it: short ones with exec, longer ones with the commands API.
3. **Move files** in and out with volumes and the S3-compatible API, or download what you need from inside.
4. **Terminate** it when you're done. Timeouts stop it if you forget.

## Use sandboxes with a coding agent

The fastest way to start is to let your coding agent set things up. In the [Runpod console](https://console.runpod.io/sandboxes), open **Sandboxes** and select **Setup guide**. It gives you:

- An API key for your agent to read from `RUNPOD_API_KEY`.
- A prompt to paste into Claude Code, Codex, Cursor or another coding agent. The agent learns the API, creates a sandbox, runs a command and cleans up.
- A skill file you can add to your agent.
