Sandboxes are in beta. These limitations reflect current behavior and will change:

- **Commands can return `409` right after the sandbox reports `RUNNING`.** The container may still be starting. Retry when the code is `sandbox_starting`.
- **Only HTTP ports work.** `tcp` and `udp` ports return `400`, so you can only connect over SSH through the Runpod proxy, not directly.
- **Network volumes can't be written to in some data centers yet.** Use a global volume until this is fixed. On a network volume, a process that doesn't run as root can't create files.
- **Global volumes don't support every file operation.** `chmod` and `utime` fail, files can't be made executable, and `git init` fails.
- **Outbound traffic can't be restricted yet.** `egressMode` and `egressAllowlist` are stored but not enforced.
- **Use an API key with full access.** Scoped API keys don't work with sandboxes yet.
- **Creating many sandboxes at the same time can fail.** If a create fails, retry it with a new `Idempotency-Key`.
- **A sandbox can keep billing after its container exits.** If a command returns `409` with code `container_exited`, terminate the sandbox and create a new one.
- **`/tmp` uses memory.** Large files in `/tmp` count against the sandbox's memory and can stop it. Write large files to your home directory or a volume.
- **Cost centers and projects don't support sandboxes yet.**
