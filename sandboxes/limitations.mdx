Sandboxes are in beta. These limitations reflect current behavior and will change:

- **Commands can return `409` right after the sandbox reports `RUNNING`.** The container may still be starting. Retry when the code is `sandbox_starting`.
- **Only HTTP ports work.** `tcp` and `udp` ports return `400`, so SSH works only through the Runpod proxy. See [Networking](/sandboxes/networking).
- **Network volumes can't be written to in some data centers yet,** including EU-RO-1. Use a global volume until this is fixed. See [Storage](/sandboxes/storage#mount-a-network-volume).
- **Global volumes aren't a full file system.** See [global volume limitations](/storage/globalvolume/overview#limitations).
- **Outbound traffic can't be restricted yet.** See [Outbound access](/sandboxes/networking#outbound-access).
- **Use an API key with full access.** Scoped API keys don't work with sandboxes yet.
- **Creating many sandboxes at the same time can fail.** If a create fails, retry it with a new `Idempotency-Key`.
- **A sandbox can keep billing after its container exits.** If a command returns `409` with code `container_exited`, terminate the sandbox and create a new one.
- **`/tmp` uses memory.** Large files there can stop the sandbox. See [Container disk](/sandboxes/storage#container-disk).
- **Cost centers and projects don't support sandboxes yet.**
